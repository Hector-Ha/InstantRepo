# Use catalog-driven env drafts with vault-backed credentials

InstantRepo will treat `.env` setup as a first-class setup domain, not a plain template copy. Env drafts will be driven by a bundled Env Default Catalog shipped through app patches, App Topology detection, stable generated local secrets, and a Dev Default Allocator that can choose coherent local ports, URLs, and datastore defaults without relying on same-name env linking.

Service credentials are different from generated local secrets. InstantRepo must not invent provider keys, but it may store user-approved service credentials in the operating system credential store through User Env Vault. Vault values are masked by default, require explicit repo-scoped approval before use, keep local usage records until the user deletes them, and never outrank catalog classification rules. Generated local secrets stay repo-local in `.env` draft content and are not stored in the vault or Local App Database.

Env intelligence improves through curated Env Catalog Patches and opt-in Env Pattern Contributions that send env var names and public repo context only, never values or key formats. Draft values carry provenance so catalog or AI patches can update blanks, placeholders, and low-confidence app-generated values without overriding existing user/workspace values or vault-backed credentials. AI Advisor may help with env review through bounded AI Env Review Bundles and structured Env Patches, but it must not receive secret values, vault values, full `.env` files, or full source files by default; the app remains responsible for validating and applying any suggested draft changes.
