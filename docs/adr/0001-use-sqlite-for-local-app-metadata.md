# Use SQLite for local app metadata

InstantRepo stores clone history, installed repo records, setup sessions, step status, and diagnostic metadata in a local SQLite database. SQLite is preferred over JSON because the manager and setup history need transactional writes, queries, indexing, and migrations; it is preferred over Postgres because InstantRepo is a local desktop app and must not require users to install or run a database server before using the app. The database must be security-first: no secrets, OS credential store for AI provider keys and User Env Vault values, strict local file permissions where possible, versioned migrations from the first release, bounded retention, and redacted logs stored as local files referenced by SQLite rather than large database blobs; encryption at rest is deferred unless sensitive values must be stored later.

User Env Vault credential target keys in the OS credential store are namespaced by stable Local App Database identity. This keeps isolated app-data databases safe even when they reuse SQLite row IDs, so temp CLI or Wails runs cannot overwrite, reveal, or delete credentials that belong to normal app data.
